# M05 — Whisper vs Zipformer under severe Babble noise

M05 compares the two production STT runtime paths under the two hardest Babble conditions already generated by M04.

```text
VoiceBank clean speech
  + MS-SNSD Babble
  + SNR 5 / 0 dB
  ↓
ALSA Loopback
  ↓
Silero VAD
  ↓
Whisper Tiny.en
        vs
Zipformer 2023-06-21
  ↓
Transcript + latency + CPU/RAM
```

Fixed features:

```text
GTCRN       : OFF
Smart Turn  : OFF
Speculative : OFF
Barge-in    : ON
```

The benchmark reuses the existing M04 dataset:

```text
data/stt/ms_snsd/mixed/voicebank_prepared_15/babble/
├── snr05/
├── snr00/
└── manifest.tsv
```

No runtime/model integration code is modified. Each backend command is generated through `app.config.build_speech_command()`.

## Full benchmark

Use alternating model order across three independent runs:

```text
Run 1: Whisper  → Zipformer
Run 2: Zipformer → Whisper
Run 3: Whisper  → Zipformer
```

Commands:

```bash
python3 benchmarks/stt/M05_whisper_zipformer_babble/benchmark_model_noise.py \
  --order whisper,zipformer_2023_06_21

python3 benchmarks/stt/M05_whisper_zipformer_babble/benchmark_model_noise.py \
  --order zipformer_2023_06_21,whisper

python3 benchmarks/stt/M05_whisper_zipformer_babble/benchmark_model_noise.py \
  --order whisper,zipformer_2023_06_21
```

Each full run contains:

```text
15 samples × 2 SNR × 2 models = 60 turns
```

Three runs total:

```text
180 turns
```

Primary comparison metrics:

- Corpus WER and Exact Match;
- TOTAL mean and TOTAL p95;
- startup → READY;
- idle/active CPU;
- idle/peak RSS;
- ONNX model footprint.

`TOTAL` is the primary realtime metric because Whisper and Zipformer use different backend-specific runtime architectures. `STT` latency is kept as a diagnostic metric.
